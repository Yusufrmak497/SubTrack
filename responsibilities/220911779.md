## Technical Decisions I Took

1. **PostgreSQL Migration:** Chose PostgreSQL over SQLite for production-level relational integrity, better concurrency, and support for the 11-entity schema with cascading deletes.
2. **Rate Limiting (`slowapi`):** 60 req/min default per IP; email OTP endpoint separately capped at 3/min to prevent OTP spam abuse.
3. **M:N Tag Relationship:** Junction table `SubscriptionTagLink` allows flexible, user-defined labeling across subscriptions without duplicating tag records.
4. **Async FX Integration:** `httpx` async client with 5-second timeout; returns `502 Bad Gateway` on provider failure rather than silently returning zero.
5. **Currency Preference via `/auth/preferences`:** Stored server-side per user so preference survives device changes; PATCH endpoint for partial update.
6. **Multi-Method 2FA:** Offered TOTP, recovery codes, security question, and email OTP so users can always recover access regardless of device availability. Device trust tokens reduce friction for daily use.
7. **iCalendar Standard:** `.ics` output ensures compatibility with Google Calendar, Outlook, and Apple Calendar without requiring app-specific integrations.
8. **GSAP Animations:** Hardware-accelerated `back.out` spring animation on modal open; `clearProps: 'all'` ensures no lingering inline styles after animation completes.
9. **CI with PostgreSQL Service Container:** E2E tests run against a real PostgreSQL instance (same as production) rather than SQLite to catch migration-sensitive bugs at CI time.
10. **MSW for Unit Tests:** Mock Service Worker intercepts fetch calls at the network layer in jsdom, matching real browser behavior without coupling tests to a running server.
